# ColorOS 录音增强

一个作用于 ColorOS 系统录音机（`com.coloros.soundrecorder`）的 [LSPosed](https://github.com/LSPosed/LSPosed) 模块。

录音列表右上角菜单支持**一键批量转文本**（全部录音类型，排除回收站）；批量转写完成后可**自动生成 AI 摘要**（可开关）；原生搜索原本只能搜"摘要"，本模块为其注入了**转写正文全文搜索**能力。

> 模块无界面、无桌面图标，全部功能均在录音机进程内通过 Hook 实现。

## ✨ 功能

### 1. 一键批量转文本

在录音列表（BrowseFragment）右上角展开菜单中注入四个菜单项（位于"设置"下方）：

| 菜单项             | 行为                                                                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **转文本**         | 扫描全部录音（最新优先；标准/会议/采访/通话等全部类型，排除回收站），跳过已转完的，取最多 10 条未转的批量触发                                                                                                    |
| **转全部**         | 同上但不设上限，库里所有未转的录音全部入队                                                                                                                                                                       |
| **生成摘要:开/关** | 开关项（点击切换，状态持久化，默认开）：开启时每条**转文本完成后自动生成 AI 摘要**                                                                                                                               |
| **模块诊断**       | 打开状态诊断浮层：宿主/模块版本、功能开关、队列运行状态、**每个 hook 点的定位结果**（目标 / 对应功能 / 状态 / 实际定位到的类），支持一键复制文本。模块失效时截图或粘贴该页即可快速定位是宿主哪个版本改了哪个符号。详见 [doc/模块诊断功能.md](doc/模块诊断功能.md) |

批量任务由**事件驱动的串行队列**（`ConvertQueue`）逐条推进：每条转写完成后（Hook 完成回调）延迟 3s 再触发下一条，长录音也会等到真正转完才继续；另设超时保底防止队列卡死。

### 2. 转写完成后自动生成摘要

与播放页（PlaybackActivity）手动点"生成摘要"走**同一条云端管道**——复用宿主无 UI 的 `AISummaryTaskManager` 投递入口（官方 AI 指令同款路径），结果由宿主自己落库（`files/summary_bundles/bundle_xxx`），模块不碰存储格式。

- **串行 + 间隔防限流**：摘要生成是云端 API，一条一条生成，每条之间间隔 5s；转写与摘要共用一条云端串行通道——上一条摘要没跑完，下一条转写不会提前发起；
- **开关即时生效**：菜单点击"生成摘要:开/关"切换并持久化，批量中途切换也生效；
- **异常兜底**：
  - "内容过短，无法生成摘要"（错误码 10016）→ 该条跳过，队列继续；
  - 管道忙 / 限流（10002）→ 冷却 30s 自动重试，最多 2 次；
  - 已有摘要缓存、未完成转写的记录直接跳过；
  - 单条超时 180s（与官方超时一致）保底推进，防止队列卡死。

### 3. 转写正文全文搜索

原生搜索只能命中"摘要"（AI 生成，非全部录音都有）。本模块在后台为每份转写 txt 建立 SQLite FTS 索引，并将命中结果**伪装成摘要条目**注入原生搜索结果：

- 关键词高亮、点击跳转播放页等 UI 全部复用宿主原生逻辑，零自定义界面；
- 注入条目统一打上「转文本：」标签，与原生"摘要"区分；
- 转写完成 / 录音删除时增量同步索引（Hook 落库口与删除口），另有一次搜索前懒对账兜底清理。

## 🔧 实现原理

```
用户点击列表菜单"转文本 / 转全部"
        │
        ▼
扫描 records 表（record_type IN (0,1,2,3,5,6,7) AND is_recycle = 0，
最新优先，跳过已转完的）
        │
        ▼
ConvertQueue 串行队列 ──▶ TriggerHandle（去重/防重）──反射──▶ startConvertTask
        │ 完成回调 hook（在线/离线/后台三条链路）
        ▼
开关开 ──▶ SummaryQueue 摘要串行队列（复用宿主 AISummaryTaskManager 无 UI 投递管道）
        │ 完成回调 hook
        ▼
ConvertIndexer → FTS 索引
        │
搜索时：摘要关键字查询 hook ──after──▶ FTS 查询转写正文，注入结果
```

**Hook 定位采用两层策略，兼顾稳定性与跨版本兼容：**

- **层 1**：直接 `Class.forName` 已知类名（录音机的 Kotlin 业务类大多未混淆）；
- **层 2**：层 1 失败时，用 [DexKit](https://github.com/LuckyPray/DexKit) 在后台线程按结构特征 / 字符串锚点（日志串、SQL 串、构造器签名、内联资源 id）重新定位（不阻塞 App 启动），跨版本漂移也能兜底。转文本触发与摘要管道（后者核心符号是单字母混淆名，漂移风险最高）都接入了层 2；定位结果进程内缓存，每进程至多解析一次；
- **状态可视化**：每个 hook 点的定位结果都会上报到 `HookStatus` 注册表，菜单"模块诊断"打开诊断浮层可随时查看（含定位层级与实际解析到的类名）。

所有 Hook 均为 `PROTECTIVE` 异常模式 + 全量 try-catch：模块自身异常只进 Xposed 日志，绝不影响录音机原有流程。

**核心源码结构**（`app/src/main/java/.../lsp_colorOSRecord/`）：

| 文件                                          | 职责                                                                            |
| --------------------------------------------- | ------------------------------------------------------------------------------- |
| `ModuleMain.kt`                               | 模块入口（libxposed 现代 API）                                                  |
| `HookInstaller.kt`                            | Hook 安装编排 + DexKit 兜底定位                                                 |
| `TriggerHandle.kt`                            | 转文本触发器（去重、防重、反射调用）                                            |
| `ConvertQueue.kt`                             | 完成事件驱动的串行转文本队列                                                    |
| `ScanButtonInjector.kt`                       | 注入"转文本 / 转全部 / 生成摘要开关 / 模块诊断"菜单项                           |
| `HookStatus.kt`                               | Hook 点状态注册表 +「模块诊断」诊断浮层                                         |
| `SummaryQueue.kt`                             | 转写后自动摘要：开关持久化 + 串行摘要队列（复用宿主 AISummaryTaskManager 管道） |
| `SummaryDexKitResolver.kt`                    | 摘要管道混淆符号的 DexKit 层 2 定位                                             |
| `SearchInjector.kt`                           | 转写正文搜索结果注入                                                            |
| `ConvertIndexer.kt` / `ConvertSearchIndex.kt` | FTS 索引调度与实现                                                              |
| `XLog.kt`                                     | 日志封装                                                                        |

## 📱 兼容性

- **宿主**：ColorOS 系统录音机 `com.coloros.soundrecorder`，实际开发与测试基于 **17.8.8** 版本；
- **框架**：LSPosed（libxposed 现代 API，API ≥ 102）；
- 其他 ColorOS / realme UI 版本未逐一验证，类名漂移时依赖 DexKit 兜底，欢迎反馈 issue。

## 🔨 构建

要求：JDK 17 + Android SDK 37（AGP 9 已内置 Kotlin 编译支持）。

```bash
./gradlew assembleRelease
```

- 版本号全自动：`versionCode` = 当前分支提交总数，`versionName` = 最近的 `v*` tag（如 `v1.2` → `1.2`），无需手动维护；
- 正式签名：在项目根目录创建 `keystore.properties`（已被 gitignore，不进仓库）：

  ```properties
  storeFile=release.jks
  storePassword=xxxxxx
  keyAlias=xxxxxx
  keyPassword=xxxxxx
  ```

  该文件不存在时自动回退 debug 签名，便于本地验证。

## 📥 安装

1. 构建 APK 后安装到手机（或从 [Releases](https://github.com/imRoxy2222/lsp_colorOSSSoundRecordEnhance/releases) 下载）；
2. 在 LSPosed 中启用本模块；
3. 作用域勾选 **ColorOS 录音机**（`com.coloros.soundrecorder`，模块声明为静态作用域，一般会自动勾选）；
4. 重启系统界面或重启手机，打开录音机验证。

验证方式：打开录音机后，在 LSPosed 管理器日志中能看到 `module loaded` / `hooked ...` 等日志；点右上角菜单"转文本"后出现逐条"转文本已完成"提示。

## 🙋 FAQ

**Q：录音会自动转文本吗？**
不会。转文本唯一入口是列表右上角菜单的"转文本 / 转全部"（入库自动触发路线实测不可靠，已移除）。record_type 各取值含义见 [doc/录音Record_Type描述.md](doc/录音Record_Type描述.md)。

**Q：QQ / 微信电话录音为什么没有自动转？**
VoIP 通话结束时录音机进程通常不在运行。打开录音机后点右上角菜单的"转文本"或"转全部"即可批量处理。

**Q：搜索里出现的「转文本：」结果是什么？**
这是模块注入的转写正文全文搜索命中，非原生摘要。App 原有的关键词高亮和点击跳转均正常可用。
